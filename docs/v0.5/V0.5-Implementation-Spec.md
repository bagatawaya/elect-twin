**Tools #1–#6 · Approved 2026-11-12 · Companion to `migrations/0001_v05.sql` + `migrate.py`**

## 0. TL;DR

V0.5 ships six deterministic primitives on top of the verified local foundation (`twin.py` / `collaboration.py` / `zoo.py`, stdlib-only, 3-vault SQLite): (1) Airlock Outbound Privacy Diff & Key-Allowlist Sanitizer, (2) 1-Click Sanitized Crew Forking & Model Auto-Rebinder, (3) Blind Scrimmage Toggle & Model Arbitrage Router, (4) openzoo-mcp stdio server (MCP Server role; Host role deferred to V0.8), (5) Porcelain & Ink Verdict Card renderer, (6) Hybrid Local Vault Grounding (FTS5 now, sqlite-vec via Capability Pack). All security invariants are pure-stdlib Python that must pass a 50-case prompt-injection red-team suite before merge. External research verification (16 searches, 2026-11-12) confirmed the roadmap's stack choices but **corrected four licensing facts** — see §2 before writing any media/QC code.

## 1. Scope, Constraints & Non-Goals

**Hard constraints (non-negotiable):**

| # | Constraint | Enforcement |
|---|-----------|-------------|
| C1 | Core runtime stays **zero external pip dependencies** (Python 3.12+ stdlib only) in `twin.py` / `collaboration.py` / `zoo.py` | CI import-lint: these three files may not `import` anything outside stdlib |
| C2 | Core installer stays **< 50 MB**; anything heavy lives in `~/Library/Application Support/Elect Twin/packs/` (macOS) / `%APPDATA%\Elect Twin\packs\` (Windows) with SHA-256 verification | `packs.py` downloader refuses unpack without matching sha256 |
| C3 | Security invariants (airlock, amber gate, budget locks, vault isolation) are **first-party code** — never delegated to an agent framework | Code review + `tests/test_prompt_injection_airlock.py` |
| C4 | **No automatic retry** on timed-out external calls; timeout → `PAUSED_UNCERTAIN` | `authoritative_tool_approvals` state machine |
| C5 | Never log prompts, tokens, keys, or request bodies (existing `Handler.log_message` policy extends to all new modules) | grep-audit in CI |

**Non-goals for V0.5 (deferred):** MCP Host role + MCP Apps iframe (V0.8, blocked on 2026-07-28 spec hardening); Playwright/CDP browser (V0.8); personal connectors (V0.8); remote co-pilot WebRTC (V1.0); media pipeline + W-12 QC (V0.8, license corrections in §2.4 must land first).

**Critical-path risk from roadmap §6.2:** `rooms-reference/Elect Twin Rooms.app` is a precompiled arm64 PyInstaller binary without `rooms.py` source. V0.5 does **not** depend on it — the migration and all six tools run inside the existing `Twin`/`SoloRoomStore` engines. The rooms-source-recovery prototype is tracked as a parallel spike, not a V0.5 blocker.

### 2.2 Correction — InsightFace is a commercial trap

The roadmap's W-12 QC gate ("InsightFace ArcFace 512-d cosine ≥ 0.72") **cannot ship in a commercial product as written**. InsightFace *code* is MIT, but every pretrained model pack (buffalo_l/m/s, antelopev2) is **non-commercial research only**; commercial use requires a separate license from InsightFace. This also infects **LatentSync**, which imports InsightFace for face detection.

| Component | Roadmap says | Verified fact | Required action |
|---|---|---|---|
| InsightFace (W-12 identity gate) | Apache/MIT implied | Code MIT; **weights non-commercial** | Replace with OpenCV **YuNet + SFace** (Apache-2.0, commercial-safe; 128-d embeddings, cosine threshold ~0.50) or budget an InsightFace commercial license. [LocalAI license table](https://localai.io/docs/features/face-recognition/index.html) |
| LatentSync 1.5 | "Apache 2.0 (100% Commercial)" | **Code Apache-2.0; weights OpenRAIL++** (commercial allowed *with use restrictions*); 1.5 needs ~8 GB VRAM | License manifest must carry OpenRAIL++ terms; strip/replace InsightFace detector (MediaPipe or YuNet) before any paid deployment. [GitHub issue #370](https://github.com/bytedance/LatentSync/issues/370) |

### 2.3 Correction — LiteLLM needs a carve-out audit

Core repo is MIT, but `enterprise/` is separately licensed (production use tied to a BerriAI subscription), and the MIT/enterprise boundary is enforced by an unverified boolean — several "Enterprise" features are reachable from MIT code. Separately, LiteLLM was a **TeamPCP supply-chain victim (March 2026)**. Actions: (a) pin exact versions with hash verification in `packs/`; (b) import only the SDK surface (`litellm.completion` via `BaseProviderAdapter`), never the proxy server; (c) re-audit the LICENSE carve-out at each upgrade. [license analysis](https://www.bestfreewebresources.com/litellm-alternatives-local-llm), [gating issue](https://github.com/BerriAI/litellm/issues/34241)

### 2.4 Correction — Chatterbox is archived; OWASP edition pinning

- **Chatterbox (MIT) is retired research**: Resemble AI pivoted to deepfake detection (Aug 2026); repo stays public but unmaintained. Outputs carry the PerTh watermark. Acceptable as a pinned Capability Pack, but do not build V0.8's voice tier solely on it — Kokoro-82M (Apache-2.0, actively maintained) remains the primary. [Cartesia license table](https://www.cartesia.ai/learn/open-source-tts)
- **OWASP pinning**: cite **LLM Top 10 2026** (published 2026-08-03; Excessive Agency moved up to **LLM03:2026**) and the **Top 10 for Agentic Applications 2026 (ASI01–ASI10, published 2025-12-09)**. The red-team suite in §7 maps cases to these IDs. [edition guide](https://nhimg.org/owasp-top-10-for-llm-applications-guide), [agentic list](https://www.promptfoo.dev/docs/red-team/owasp-agentic-ai/)
- **0xSplits**: not verified in this research pass (source lookup failed). Treat the V1.0 splits item as "unverified — re-source before spec'ing" (§9).

| 8 | `telemetry_inferences` | every call: tokens, ttft, cost, qc_pass, scrimmage outcome | #3 |
| 9 | `documents` / `document_chunks` | ingestion provenance; FTS5 external-content index | #6 |

| 11 | `context_cache_entries` | SHA-256 of pinned prefixes → provider cache API handles | V0.5 seed, V0.8 full |

**File permissions on migration:** runner `chmod 0600` on `projects.sqlite3` after open (matches roadmap 3-vault posture); migration runs inside a single transaction; `PRAGMA user_version` is not used (we use `schema_migrations`).

## 5. Tool Specifications

### Tool #1 — Airlock Outbound Privacy Diff & Key-Allowlist Sanitizer (`security/airlock.py`)

**Contract:** `sanitize(payload: dict, grant: room_tool_grants row) -> tuple[dict, diff_report]`.

- Allowlist schema per direction: `{'agent_id','room_id','turn_seq','sanitized_markdown','probability_lock'}` for zoo-bound payloads. Anything else is **stripped, not rejected**, and every strip is recorded in `diff_report` with path + reason.
- Deterministic strippers (regex over bytes, no LLM): absolute paths (`/Users/...`, `C:\Users\...`, `/home/...`), email addresses, IPv4/IPv6, `sk-`-style token shapes, and any value matching `SESSION_KEYS` patterns read from a runtime-injected dict (never from disk).
- **Privacy Diff render:** Git-style green/red line diff between raw and sanitized JSON, surfaced in the Right Inspector Drawer before any SHARED_ROOM / PUBLIC_ZOO send. The diff view is generated by `difflib` (stdlib).
- **Key-Allowlist for tool descriptions** (MCP rug-pull defense, MCP-server role prep): `hash_tool_schema(tools_list_json) -> sha256`; description fields truncated to 160 chars + parameter schema only before entering any prompt.

**Tests:** 30 unit cases in `tests/test_airlock.py` (path shapes per OS, zero-width unicode, nested JSON, unicode homoglyph emails); all 50 red-team transcripts must pass §7.

### Tool #2 — 1-Click Sanitized Crew Forking & Smart Model Auto-Rebinder (`crews/fork.py`)

**Contract:** `fork_crew(blueprint_json: bytes, session_keys: dict) -> crew_id`.

- Strict JSON-schema validation: only `role_slug`, `role_category`, `turn_order`, `tool_archetype` survive; **all free-text fields generated by peer agents are dropped at parse time** (before they can reach a prompt).
- Rebind: for each required model slot, pick from the user's active `SESSION_KEYS` using a deterministic priority (exact provider match → same modality → any active key), record in `model_bindings` with provenance.
- Idempotent on `(blueprint_sha256, room_id)` — re-forking returns the existing crew.

**Tests:** poisoned blueprints (injected instructions inside `role_slug`, oversized fields, wrong types); rebinding with missing keys yields an explicit `NEEDS_KEY` status row, never a silent fallback to an unpaid tier.

### Tool #3 — Blind Scrimmage Toggle & Personal Model Arbitrage Router (`crews/scrimmage.py`)

**Contract:** `run_scrimmage(task_category, candidate_models[2], prompt_bundle) -> match_id`; `scorecard(task_category) -> recommendations`.

- Blind: model identities hidden in the UI until the human votes; votes land in `scrimmage_votes` with the human's pick and reason tag.
- Router objective (deterministic SQL over `telemetry_inferences`):
  `EffectiveCost(m,t) = (C_attempt + C_tool_fees) / P(QC pass ∩ human lock | m,t)`, computed only when n ≥ 10 per category; below n, the router refuses to recommend (honest "insufficient data" state — no fabricated win-rates).
- Hard budget: `budget_reservations` holds worst-case USD before socket open; timeout → `PAUSED_UNCERTAIN`, **zero retries** (C4).

**Tests:** vote anonymity (no model_id leakage into UI payload), n<10 refusal, reservation release on failure, timeout idempotency.

### Tool #4 — openzoo-mcp stdio Server (`mcp_server/openzoo_server.py`)

Six read-mostly tools over stdio JSON-RPC 2.0, 2026-07-28 protocol revision, stdlib implementation (no `mcp` SDK dependency in V0.5 — the SDK is a V0.8 pack candidate):

| Tool | Access |
|---|---|
| `openzoo_conclave_despin` | zoo.sqlite3 read |
| `openzoo_alpha_stress_test` | zoo.sqlite3 read |
| `whats_the_line_calibrate` | zoo.sqlite3 read |
| `opentwin_vault_query` | projects.sqlite3 **read-only**, topics with `mcp_exportable=1` only |
| `opentwin_preview_sanitized_share` | returns airlock diff report without sending |
| `openzoo_render_verdict_card` | delegates to Tool #5 |

- `initialize` negotiates `protocolVersion: "2026-07-28"`; capabilities declared minimally (no elicitation/tasks claims — V0.5 server never requests them).
- Every tool call passes through `security/gates.py`: capability tier from `room_tool_grants`, Amber gate → human modal for anything above `GREEN_READ`.
- Schema-hash pinning: on server start, hash each exposed tool's description; mismatch vs `schema_migrations`-stored hash blocks startup loudly.

**Tests:** stdio handshake transcript test; vault_query refuses non-exportable topics; token never appears in any log line.

### Tool #5 — Porcelain & Ink Verdict Card (`render/verdict_card.py`)

- Pure-function SVG composer (stdlib `xml.sax.saxutils` escaping) at **1200×675**, then optional PNG via a Capability Pack renderer (not bundled).
- Layout: Opening Spread → Turn-4 Concessions → Final Accord / Preserved Dissent; watermark = twin handle; QR/deep-link is a deterministic string — actual QR raster generation is V0.8 (needs a pack).
- No external fonts, no network fetches; all text measured with a fixed char-width table to keep rendering deterministic cross-platform.

**Tests:** golden-file SVG diff; XSS attempt strings (`<script>`, `onload=`) escaped in output; CJK handles render (length table covers wide chars).

### Tool #6 — Hybrid Local Vault Grounding (`vault/`)

- **FTS5 now** (native SQLite): `document_chunks` external-content table, BM25 ranking, snippet extraction — zero new dependencies.
- **sqlite-vec when packed:** `packs.py` downloads the platform `.dylib`/`.dll` + records sha256 in `context_cache_entries`-adjacent `pack_manifest` row (created by runner); `vault/search.py` falls back to FTS5-only when the vec table is absent. Pre-v1 caveat from §2.1: chunk counts ≤ 100k per vault, enforced with a hard ingestion cap + user-facing notice.
- **Ingestion:** pypdf/pdfplumber and duckdb are *pack-tier* optional imports guarded by `try/except ImportError`; without packs, plain-text/markdown/CSV ingest still works via stdlib. Whisper and tree-sitter are V0.8 packs.
- **Claims ledger (`vault/claims.py`):** before a synthesis turn locks a decision, a deterministic verifier resolves every `` tag against `document_chunks` byte spans; failures demote the claim to `MODEL_INFERENCE` and stale sources (> `freshness_ttl_days`) get `[⚠️ STALE SOURCE]`. This is pure Python — no model in the loop.

**Tests:** round-trip ingest→search→verify; ledger demotion on fabricated quotes; FTS5-only fallback path runs with zero packs installed.
